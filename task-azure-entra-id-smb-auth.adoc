= 在 Cloud Volumes ONTAP 上為 SMB 設定 Microsoft Entra ID 驗證
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ./media/


[role="lead"]
您可以設定 Cloud Volumes ONTAP ，使其透過 https://www.microsoft.com/en-in/security/business/identity-access/microsoft-entra-id["Microsoft Entra ID"^]對存取 SMB 共享的使用者進行驗證，從而為混合雲上的 Cloud Volumes ONTAP 使用者啟用身分支援。先前，驗證需要使用內部部署的 Active Directory （AD） 來管理網域使用者的身分。透過 Microsoft Entra ID ，您可以在保持混合使用者無縫存取的同時，使用雲端型驗證。


NOTE: 此功能以公開預覽版的形式提供，且只能使用 ONTAP CLI 進行設定。NetApp Console 整合尚未推出。在 CLI 中，SMB 操作使用 `cifs`命令前綴，因為 SMB （伺服器訊息區塊）是 Common Internet File System （CIFS） 協定的現代名稱。

.關於此任務
從 Cloud Volumes ONTAP 9.19.1 開始，您可以使用 Microsoft Entra ID 來驗證使用混合身分的 SMB 使用者。混合身分是透過 https://learn.microsoft.com/en-us/entra/identity/hybrid/connect/whatis-azure-ad-connect["Microsoft Entra Connect"^]從內部部署 Active Directory（AD）同步至 Microsoft Entra ID 的使用者帳戶。

Cloud Volumes ONTAP 接受來自內部部署 AD 和 Microsoft Entra ID 的 SMB 驗證。這使您能夠在保留現有 AD 基礎架構的同時，新增雲端身分支援。

Cloud Volumes ONTAP 9.19.1 及更新版本也支援  `icacls` 命令，以管理已裝載共享上 Entra ID 身分的檔案和資料夾權限。

.開始之前
* 您必須執行 Cloud Volumes ONTAP 9.19.1 或更高版本。
* 您必須擁有作用中的 Azure 訂閱。
* 您必須在 Microsoft Entra ID 租戶中擁有具有 https://learn.microsoft.com/en-us/entra/identity/role-based-access-control/permissions-reference#global-administrator["全域系統管理員"^] 權限的使用者帳戶。
* 存取 SMB 共享的用戶端電腦必須已混合加入 Microsoft Entra。
* 您必須擁有可連線至 Microsoft Entra ID 的內部部署 AD 網域控制器。
* 您必須擁有一個具備資料 LIF 的儲存設備 VM，以及可用於 SMB 伺服器和共享的彙總。
* 儲存設備虛擬機器和用戶端虛擬機器必須能夠解析所需的 Microsoft Entra ID 端點，並透過網路與其通訊。




[[step-1-register-an-application-in-microsoft-entra-id]]
[[azure-app]]
== 步驟 1：在 Microsoft Entra ID 中註冊應用程式

您必須在 Microsoft Entra ID 中註冊應用程式，以便 Cloud Volumes ONTAP 在 SMB 設定期間能夠對租戶進行驗證。Cloud Volumes ONTAP 使用此註冊中的憑證代表您建立、修改和刪除應用程式物件。完成此步驟後，您將收集下列憑證以供在 <<ontap-config,步驟 3>> 中使用：

* *tenant-id*: 您組織的 Microsoft Entra ID 執行個體的唯一 GUID。
* *client-id*：Entra ID 應用程式的唯一識別碼。
* *client-certificate*：用於驗證應用程式的憑證。


.步驟
. https://learn.microsoft.com/en-us/entra/identity-platform/quickstart-register-app["註冊應用程式"^] 在 Azure 入口網站中。選擇 *僅限此組織目錄中的帳戶（單一租戶）* 作為支援的帳戶類型。
. 從已註冊應用程式的 *概覽* 頁面中，複製並儲存 *應用程式（用戶端）ID* 和 *目錄（租戶）ID*。
. 為應用程式註冊指派以下 Microsoft Graph API 權限：
+
** *Application.ReadWrite.OwnedBy*
** *User.Read*
** *User.Read.All*
+
若要指派權限，請前往 *API 權限 > 新增權限 > Microsoft Graph > 應用程式權限*，選取每個權限，然後選取 *授予管理員同意 <tenant-name>* 以啟動它們。

+

NOTE: 與您的 Microsoft Azure 系統管理員合作，確認您組織安全性原則所需的最低權限。



. 上傳憑證以驗證應用程式註冊。前往 *Certificates & secrets > Certificates > Upload certificate*，並上傳 `.cer`、 `.pem` 或  `.crt` 格式的檔案。
+

NOTE: 請使用由憑證授權單位簽發的憑證。雖然支援自簽憑證，但不建議在生產環境中使用。

. 選擇 *授予管理員同意* 以啟動權限。




[[step-2-set-up-on-premises-active-directory]]
[[on-prem-ad]]
== 步驟 2：設定內部部署 Active Directory

設定本機 AD 網域控制器，將使用者和群組同步到 Microsoft Entra ID，並設定裝置參加設定，以便混合身分可用於 SMB 驗證。請參閱 https://learn.microsoft.com/en-us/entra/identity/hybrid/connect/plan-connect-design-concepts["關於 Entra Connect 的 Microsoft 文件"^]。

.步驟
. 將 Windows 伺服器設定為內部部署 AD 網域的網域控制器，例如 `contoso.com`。
. 建立與 Microsoft Entra ID 同步的 AD 使用者和群組。
. 設定 _網站到區域指派清單_ 群組原則，以允許加入網域的用戶端與 Microsoft Entra ID 驗證服務通訊。
+
前往：*gpedit.msc > 系統管理範本 > Windows 元件 > Internet Explorer > 網際網路控制台 > 安全性網頁 > 指派網站到區域的清單*

. 以區域值 *1* 新增下列各個 URL：
+
[listing]
----
https://enterpriseregistration.windows.net
https://login.microsoftonline.com
https://device.login.microsoftonline.com
https://autologon.microsoftazuread-sso.com
https://login.microsoft.com
----
. 安裝 https://entra.microsoft.com/#view/Microsoft_AAD_Connect_Provisioning/AADConnectMenuBlade/~/ConnectSync["Microsoft Entra Connect | Connect Sync"^]並使用您的全域系統管理員帳戶進行設定：
+
.. https://learn.microsoft.com/en-us/entra/identity/devices/hybrid-join-plan["規劃您的 Microsoft Entra 混合參加實作"^]。請參閱 https://learn.microsoft.com/en-us/entra/identity/devices/hybrid-join-control["Microsoft Entra 混合參加目標部署"^]。
.. 為每個 https://learn.microsoft.com/en-us/windows-server/identity/ad-ds/plan/understanding-the-active-directory-logical-model["Active Directory 邏輯模型"^]設定服務連接點（SCP），並提供 AD 系統管理員憑證。
+
Azure Microsoft Entra Connect 將內部部署 AD 使用者和群組同步至 Microsoft Entra ID，並啟用混合裝置參加。



. 確認使用者和群組已同步到 Microsoft Entra ID。同步後的使用者會顯示與您的租戶網域相符的 UPN 後綴，例如 `user@<tenant>.onmicrosoft.com`。有關設定後可以執行的其他任務，請參閱 https://learn.microsoft.com/en-us/entra/identity/hybrid/connect/how-to-connect-post-installation["Microsoft 文件：後續步驟以及如何管理 Microsoft Entra Connect"^]。




[[step-3-configure-the-smb-server-on-cloud-volumes-ontap]]
[[ontap-config]]
== 步驟 3：在 Cloud Volumes ONTAP 上設定 SMB 伺服器

在 Cloud Volumes ONTAP 儲存設備 VM 上設定 SMB 伺服器，以使用您在 <<azure-app,步驟 1>> 中建立的應用程式註冊憑證，透過 Microsoft Entra ID 驗證 SMB 檔案存取。


NOTE: 在建立 SMB 伺服器之前，儲存設備虛擬機器必須已設定資料 LIF 並具有對彙總的存取。用戶端使用資料 LIF 來存取 SMB 共享。

.步驟
. 在儲存設備虛擬機器上設定 DNS，使其能夠解析 Microsoft Entra ID 端點：
+
[source, cli]
----
dns create -domains <on-premises-domain> -name-servers <dns-server-ip>
----
. 建立 SMB 伺服器並提供 Microsoft Entra ID 參數：
+
[source, cli]
----
cifs create -vserver <svm-name> -cifs-server <netbios-name> -domain <on-premises-domain-name> -auth-user-type hybrid-user -tenant-id <tenant-id> -client-id <client-id> -client-certificate <certificate>
----
. 使用 Entra ID 憑證重設 SMB Kerberos 密碼：
+
[source, cli]
----
cifs password reset -vserver <svm-name> -tenant-id <tenant-id> -client-id <client-id> -client-certificate <certificate>
----
. （可選）移除 SMB 伺服器：
+
[source, cli]
----
cifs delete -vserver <svm-name> -tenant-id <tenant-id> -client-id <client-id> -client-certificate <certificate>
----




[[step-4-register-a-client-vm-with-microsoft-entra-id]]
[[client-registered]]
== 步驟 4：向 Microsoft Entra ID 註冊用戶端 VM

當您的環境中無法直接建立遠端桌面協定 (RDP) 連線時，您可以設定一台已註冊 Entra ID 的虛擬機器來存取已加入 Entra ID 的用戶端。這台虛擬機器充當跳板機，您可以使用混合使用者憑證從該跳板機遠端登入已加入 Entra ID 的用戶端。

.開始之前
* 您必須擁有 Windows 10（21H2 或更高版本）或 Windows 11 電腦。


.步驟
. 使用本機系統管理員憑證登入 Windows 電腦。
. 前往 *設定 > 帳戶 > 存取工作或學校*，然後選擇 *連線*。
. 請輸入您的全域管理員帳戶憑證並按照提示操作。
+
該裝置已在 Microsoft Entra ID 中註冊。

. 在 Azure 入口網站的 *Entra ID > 裝置 > 所有裝置* 下，確認該裝置顯示為 *已註冊 Entra ID*。




[[step-5-join-a-client-vm-to-microsoft-entra-id]]
[[client-joined]]
== 步驟 5：將用戶端虛擬機器參加 Microsoft Entra ID

您可以將 Windows 用戶端 VM 設定為加入 Entra ID 的機器，以允許混合使用者取得雲端核發的 Kerberos 票證並裝載 ONTAP SMB 共享。如需詳細資訊，請參閱  https://learn.microsoft.com/en-us/entra/identity/devices/how-to-hybrid-join["設定 Microsoft Entra 混合參加"^] 和  https://learn.microsoft.com/en-us/entra/identity/devices/troubleshoot-hybrid-join-windows-current["疑難排解 Microsoft Entra 混合加入裝置"^]。


NOTE: 參加後，您只能使用來自在 <<client-registered,步驟 4>> 中設定之已註冊 Entra ID 機器的混合使用者憑證來存取此機器。

.開始之前
* 您必須擁有 Windows 10（21H2 或更高版本）或 Windows 11 電腦。
* 您必須擁有從內部部署 AD 同步的混合使用者帳戶。這些帳戶是在 <<on-prem-ad,步驟 2>> 中建立。


.步驟
. 使用本機系統管理員憑證登入 Windows 電腦。
. 前往 *設定 > 帳戶 > 存取工作或學校* 並選擇 *連線 > 將此裝置參加 Azure Active Directory*。
+
使用混合使用者帳戶完成參加。如果參加未成功完成，請參閱 https://learn.microsoft.com/en-us/answers/questions/1179294/how-to-join-device-as-azure-ad-joined-if-its-added["疑難排解 Microsoft Entra 混合加入裝置"^]。

. 在出現提示時重新啟動機器，然後在 Azure 入口網站的 *Entra ID > 裝置 > 所有裝置* 下，驗證其是否顯示為 *Entra ID Joined*。




[[step-6-configure-the-joined-vm-for-smb-access]]
[[client-config]]
== 步驟 6：設定已加入的 VM 以進行 SMB 存取

將虛擬機器加入 Microsoft Entra ID 後，您必須將其設定為取得雲端核發的 Kerberos 票證、解析 SMB 伺服器主機名稱，並允許從已註冊 Entra ID 的電腦進行 RDP 存取。

.步驟
. 在已加入 Entra ID 的虛擬機器的 hosts 檔案中新增 DNS 項目，以便它可以解析 SMB 伺服器主機名稱：
+
.. 在文字編輯器中開啟 `C:\Windows\System32\drivers\etc\hosts`。
.. 新增以下條目，將 ONTAP 資料 LIF IP 位址對應到 SMB 伺服器 FQDN：
+
[listing]
----
<lif-ip-address>  <netbios-name>.<on-premises-domain>
----


. 啟用 PKU2U 驗證原則：
+
.. 前往：
+
*gpedit.msc > 電腦設定 > Windows 設定 > 安全性設定 > 本機原則 > 安全性選項*

.. 啟用 *網路安全性：允許對此電腦的 PKU2U 驗證要求使用線上身分*。
+
如需詳細資訊，請參閱 https://learn.microsoft.com/en-us/windows/security/threat-protection/security-policy-settings/network-security-allow-pku2u-authentication-requests-to-this-computer-to-use-online-identities["PKU2U 驗證原則"^]。



. 啟用雲端 Kerberos 票據擷取：
+
.. 前往：
+
*gpedit.msc > 電腦設定 > 管理範本 > 系統 > Kerberos*

.. 啟用*允許在登入期間擷取雲端 Kerberos 票據*。


. 為 ONTAP SMB 伺服器設定 Kerberos 網域對映：
+
.. 在同一個 Kerberos 原則位置，選擇 *定義主機名稱到 Kerberos 領域的對應*。
.. 新增以下對應：
+
[listing]
----
Value name: KERBEROS.MICROSOFTONLINE.COM
Value: <netbios-name>.<on-premises-domain>
----


. 將混合使用者新增至 _Remote Desktop Users_ 群組，以允許從已註冊 Entra ID 的 VM 存取：
+
[source, cmd]
----
net localgroup "Remote Desktop Users" /add "AzureAD\<username>@<tenant>.onmicrosoft.com"
----




[[step-7-mount-the-smb-share-and-verify-access]]
[[mount-share]]
== 步驟 7：裝載 SMB 共享並驗證存取

您可以從加入 Entra ID 的用戶端裝載 SMB 共享，並驗證基於 Kerberos 的 Microsoft Entra ID 驗證是否端點對端點成功。

.步驟
. 從已註冊 Entra ID 的虛擬機器，使用遠端桌面連線，以混合使用者憑證登入已加入 Entra ID 的虛擬機器，格式如下：
+
[listing]
----
AzureAD\<username>@<tenant>.onmicrosoft.com
----
+
如果登入失敗，請選取 *更多選項* 並手動輸入憑證。如果問題仍然存在，請在遠端桌面連線用戶端的 *進階* 索引標籤中啟用 *使用 Web 帳戶*。如需詳細資訊，請參閱 https://learn.microsoft.com/en-us/entra/identity/devices/howto-vm-sign-in-azure-ad-windows["使用 Microsoft Entra ID 登入 Windows 虛擬機器"^]。

. 執行 `klist`並確認存在 `KERBEROS.MICROSOFTONLINE.COM`的 `krbtgt`票證，以驗證登入時是否已發出雲端 Kerberos 票證：
+
[source, powershell]
----
klist
----
+
範例輸出：

+
[listing]
----
Cached Tickets: (1)
#0>     Client: <username> @ <domain>
        Server: krbtgt/KERBEROS.MICROSOFTONLINE.COM @ KERBEROS.MICROSOFTONLINE.COM
        KerbTicket Encryption Type: Unknown (-1)
        Ticket Flags 0x40810000 -> forwardable renewable name_canonicalize
        Start Time: <date and time>
        End Time:   <date and time>
        Renew Time: <date and time>
        Session Key Type: AES-256-CTS-HMAC-SHA1-96
----
+
此票證的存在確認裝置已正確加入，並且可以取得雲端核發的 Kerberos 票證。

. 在 Cloud Volumes ONTAP 系統上建立 Volume 和 SMB 共享，或使用現有 Volume 和共享：


[source, cli]
----
volume create -vserver <svm-name> -volume <volume-name> -aggregate <aggregate-name> -size <size> -junction-path /<volume-name> -security-style ntfs
cifs share create -vserver <svm-name> -share-name <share-name> -path /<volume-name>
----

NOTE: Volume 必須使用 NTFS 安全樣式，以便您可以透過  `icacls` 管理 Microsoft Entra ID 身分識別的檔案與資料夾權限。

. 驗證用戶端是否可以取得 SMB 伺服器的 Kerberos 服務票證：
+
[source, powershell]
----
klist get CIFS/<netbios-name>.<on-premises-domain>
----
+
確認已傳回服務票證，且 `KdcCalled`顯示 `KdcProxy:login.microsoftonline.com`。這確認驗證是透過 Microsoft Entra ID 路由。

. 裝載 SMB 共享：
+
[source, powershell]
----
net use * \\<netbios-name>.<on-premises-domain>\<share-name>
----
. 在 Cloud Volumes ONTAP 系統上，驗證是否已建立 SMB 工作階段：
+
[source, cli]
----
cifs session show -vserver <svm-name>
----
+
工作階段輸出會顯示已連線的工作站與混合使用者，格式為 `AZUREAD\<username>@<tenant>.onmicrosoft.com`。





[[step-8-manage-file-permissions-with-icacls]]
[[dacl]]
== 步驟 8：使用 icacls 管理檔案權限

Cloud Volumes ONTAP 9.19.1 及更高版本支援  `icacls` 命令，以管理裝載的 SMB 共享上 Microsoft Entra ID 身分識別的檔案和資料夾權限。

.步驟
. 根據您要設定的存取執行相應的 `icacls`命令：
+
若要授予存取：

+
[source, cmd]
----
icacls <drive>:\<path> /grant "AzureAD\<username>@<tenant>.onmicrosoft.com":(W)
----
+
拒絕存取：

+
[source, cmd]
----
icacls <drive>:\<path> /deny "AzureAD\<username>@<tenant>.onmicrosoft.com":(W)
----

= Google Cloud 對 Cloud Volumes ONTAP 的連網需求
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ./media/


[role="lead"]
NetApp Console 在 Google Cloud 中為 Cloud Volumes ONTAP 設定連網元件，例如 IP 位址、子網路遮罩和路由。您需要確保傳出網際網路存取可用、有足夠的私人 IP 位址可用，並且已建立正確的連線。

如果你想部署 HA 對，你應該link:concept-ha-google-cloud.html["了解 HA 對在 Google Cloud 中的工作原理"]。



[[requirements-for-cloud-volumes-ontap]]
== Cloud Volumes ONTAP的要求

您的 Google Cloud 環境必須滿足以下要求。



[[requirements-specific-to-single-node-systems]]
=== 單節點系統的特定要求

如果要部署單節點系統、請確保您的網路符合下列要求。



==== 一個 VPC

單節點系統需要一個虛擬私有雲（VPC）。



==== 私人 IP 位址

對於 Google Cloud 中的單節點系統，Console 會將私人 IP 位址指派給下列各項：

* 節點
* 簇
* 儲存虛擬機
* 數據 NAS LIF
* 資料 iSCSI LIF


如果您使用 API 部署Cloud Volumes ONTAP並指定下列標誌，則可以跳過建立儲存虛擬機器 (SVM) 管理 LIF：

`skipSvmManagementLif: true`


NOTE: LIF 是與實體連接埠關聯的 IP 位址。  SnapCenter等管理工具需要儲存虛擬機器 (SVM) 來管理 LIF。



[[requirements-specific-to-ha-pairs]]
=== HA 對的特定要求

如果要部署 HA 對，請確保您的網路符合以下要求。



==== 一個或多個區域

您可以透過在多個區域或單一區域部署 HA 組態來確保資料的高可用度。建立 HA 配對時，主控台會提示您選擇多個區域或單一區域。

* 多區域（建議）
+
在三個區域部署 HA 組態，可確保在某個區域發生故障時維持持續的資料可用度。寫入效能略低於單一區域，但差異微乎其微。

* 單區
+
在單一區域中部署時， Cloud Volumes ONTAP HA 配置使用分散放置策略。此策略可確保 HA 配置免受區域內單點故障的影響，而無需使用單獨的區域來實現故障隔離。

+
這種部署模型確實降低了您的成本，因為區域之間沒有資料流出費用。





==== 四個虛擬私有雲

HA 組態需要四個虛擬私有雲（VPC），因為 Google Cloud 要求每個網路介面都位於分隔的 VPC 網路中。

建立 HA 對時，控制台會提示您選擇四個 VPC：

* VPC-0 用於資料和節點的入站連接
* VPC-1、VPC-2 和 VPC-3 用於節點和 HA 中介之間的內部通信


image:diagram_gcp_ha.png["概念圖展示了 Cloud Volume HA 對和配置所需的四個 VPC。"]



==== 子網

每個 VPC 都需要一個私有子網路。

如果您將 Console 代理程式放置在 VPC-0 中，則必須在子網路上啟用私人 Google 存取，才能存取 API 並啟用資料分層。

這些 VPC 中的子網路必須具有不同的 CIDR 範圍，且這些範圍不能重疊。



==== 私人 IP 位址

控制台會自動為 Google Cloud 中的Cloud Volumes ONTAP指派所需數量的私有 IP 位址。您需要確保您的網路有足夠的可用私有位址。

分配給 Cloud Volumes ONTAP 的 LIF 數量取決於您部署的是單節點系統還是 HA 配對。LIF 是與實體連接埠相關聯的 IP 位址。管理工具（例如 SnapCenter）需要 SVM 管理 LIF。

* *單一節點* 主控台會為單一節點系統指派四個 IP 位址：
+
** 節點管理 LIF
** 集群管理 LIF
** iSCSI 資料 LIF
+

NOTE: iSCSI LIF 透過 iSCSI 協定提供用戶端訪問，並被系統用於其他重要的網路工作流程。這些 LIF 是必需的，不應刪除。

** NAS LIF
+
如果您使用 API 部署Cloud Volumes ONTAP並指定下列標誌，則可以跳過建立儲存虛擬機器 (SVM) 管理 LIF：

+
`skipSvmManagementLif: true`



* *HA 對* 控制台為 HA 對分配 12-13 個 IP 位址：
+
** 兩個節點管理 LIF（e0a）
** 一個叢集管理 LIF（e0a）
** 兩個 iSCSI LIF（e0a）
+

NOTE: iSCSI LIF 透過 iSCSI 協定提供用戶端訪問，並被系統用於其他重要的網路工作流程。這些 LIF 是必需的，不應刪除。

** 一或兩個 NAS LIF（e0a）
** 兩個叢集 LIF（e0b）
** 兩個 HA 互連 IP 位址（e0c）
** 兩個 RSM iSCSI IP 位址（e0d）
+
如果您使用 API 部署Cloud Volumes ONTAP並指定下列標誌，則可以跳過建立儲存虛擬機器 (SVM) 管理 LIF：

+
`skipSvmManagementLif: true`







==== 內部負載平衡器

控制台會建立四個 Google Cloud 內部負載平衡器（TCP/UDP），用於管理傳入 Cloud Volumes ONTAP HA 配對的流量。無需任何設定。此資訊有助於您了解網路流量並解決安全性問題。

一個負載平衡器用於叢集管理，一個用於儲存虛擬機器 (SVM) 管理，一個用於到節點 1 的 NAS 流量，最後一個用於到節點 2 的 NAS 流量。

每個負載平衡器的設定如下：

* 一個共享的私人 IP 位址
* 一次全球健康檢查
+
預設情況下，健康檢查使用的連接埠為63001、63002、63003。

* 一個區域 TCP 後端服務
* 一個區域 UDP 後端服務
* 一條 TCP 轉送規則
* 一條 UDP 轉送規則
* 全域存取已禁用
+
儘管全域存取預設為停用，但您可以在部署後啟用它。我們將其停用的原因是跨區域流量的延遲顯著較高，且我們希望避免因意外的跨區域掛載而導致使用者體驗不佳。僅在您的業務需求需要時才啟用全域存取。





[[shared-vpcs]]
=== 共享 VPC

Google Cloud 共享 VPC 和獨立 VPC 皆支援Cloud Volumes ONTAP和控制台代理。

對於單節點系統，VPC 可以是共用 VPC 或獨立 VPC。

對於 HA 對，需要四個 VPC。每個 VPC 可以是共享的，也可以是獨立的。例如，VPC-0 可以是共用 VPC，而 VPC-1、VPC-2 和 VPC-3 可以是獨立 VPC。

共用 VPC 可讓您跨多個專案配置和集中管理虛擬網路。您可以在_主機專案_中設定共用 VPC 網絡，並在_服務項目_中部署控制台代理程式和Cloud Volumes ONTAP虛擬機器實例。

https://cloud.google.com/vpc/docs/shared-vpc["Google Cloud 文件：共享 VPC 概覽"^] 。

https://docs.netapp.com/us-en/console-setup-admin/task-quick-start-connector-google.html["查看控制台代理部署中涵蓋的所需共用 VPC 權限"^]



[[packet-mirroring-in-vpcs]]
=== VPC 中的資料包鏡像

https://cloud.google.com/vpc/docs/packet-mirroring["資料包鏡像"^]必須在部署Cloud Volumes ONTAP的 Google Cloud 子網路中停用。



[[outbound-internet-access]]
=== 出站互聯網訪問

Cloud Volumes ONTAP 系統需要傳出網際網路存取來連線至外部端點，以執行各種功能。在安全性需求嚴格的環境中，如果這些端點遭到封鎖，Cloud Volumes ONTAP 將無法正常運作。

Console 代理程式也會聯絡多個端點以進行日常作業。如需端點的相關資訊，請參閱 https://docs.netapp.com/us-en/console-setup-admin/task-install-connector-on-prem.html#step-3-set-up-networking["查看從控制台代理聯繫的端點"^]和 https://docs.netapp.com/us-en/console-setup-admin/reference-networking-saas-console.html["準備好使用控制台的網絡"^]。

[[firewall-rules]]
=== 防火牆規則

控制台建立 Google Cloud 防火牆規則，其中包含Cloud Volumes ONTAP成功運作所需的入站和出站規則。您可能希望參考連接埠以進行測試，或者您喜歡使用自己的防火牆規則。

Cloud Volumes ONTAP 的防火牆規則需要同時設定傳入和傳出規則。如果您正在部署 HA 組態，以下是 VPC-0 中 Cloud Volumes ONTAP 的防火牆規則。

HA 組態需要兩套防火牆規則：

* 針對 VPC-0 中的 HA 組件的一組規則。這些規則允許對Cloud Volumes ONTAP進行資料存取。
* 另一組規則適用於 VPC-1、VPC-2 和 VPC-3 中的 HA 元件。這些規則開啟 HA 元件之間的傳入和傳出通訊。<<rules-for-vpc,了解更多>>。



TIP: 正在尋找有關 Console 代理程式的資訊？ https://docs.netapp.com/us-en/console-setup-admin/reference-ports-gcp.html["查看控制台代理的防火牆規則"^]



==== 入站規則

新增Cloud Volumes ONTAP系統時，您可以在部署期間選擇預先定義防火牆策略的來源篩選器：

* *僅限選定的 VPC*：入站流量的來源過濾器是Cloud Volumes ONTAP系統的 VPC 子網路範圍和控制台代理程式所在的 VPC 子網路範圍。這是推薦的選項。
* *所有 VPC*：入站流量的來源過濾器是 0.0.0.0/0 IP 範圍。

[[rules-for-vpc]]
==== VPC-1、VPC-2 和 VPC-3 的規則

在 Google Cloud 中，HA 配置部署在四個 VPC 中。  VPC-0 中的 HA 設定所需的防火牆規則是<<防火牆規則,以上所列的Cloud Volumes ONTAP>>。

同時，為 VPC-1、VPC-2 和 VPC-3 中的執行個體所建立的預定義防火牆規則支援透過所有協定和連接埠進行入站通訊。這些規則支援 HA 節點之間的通訊。

從 HA 節點到 HA 中介的通訊透過連接埠 3260（iSCSI）進行。


NOTE: 為了讓新的 Google Cloud HA 配對部署具備高寫入速度，VPC-1、VPC-2 和 VPC-3 的最大傳輸單元（MTU）必須至少為 8,896 位元組。如果您選擇將現有的 VPC-1、VPC-2 和 VPC-3 的 MTU 升級到 8,896 位元組，則必須在組態過程中關閉所有使用這些 VPC 的現有 HA 系統。



[[infrastructure-manager-configuration-in-private-mode-or-protected-environments]]
=== 私有模式或受保護環境中的 Infrastructure Manager 組態

如果您想在私有模式下或在受 VPC Service Controls 保護的專案中部署 Cloud Volumes ONTAP 9.16.1 或更新版本，您需要進行一些組態變更，以便 Cloud Volumes ONTAP 可以使用 Google Cloud Infrastructure Manager 作為部署服務，而不是 Deployment Manager。

.開始之前
* 請確認您的 Cloud Volumes ONTAP 系統為 9.16.1 或更新版本。如果不是，請升級您的系統。請參閱 https://docs.netapp.com/us-en/storage-management-cloud-volumes-ontap/task-updating-ontap-cloud.html["升級Cloud Volumes ONTAP"]以取得指示。
* 請確保已啟用 Google Cloud API。請參閱 https://docs.netapp.com/us-en/console-setup-admin/task-install-agent-google-gcloud.html#step-5-enable-google-cloud-apis["啟用 Google Cloud API"^]。
* 請確保已啟用 Cloud Build API。請參閱  https://console.cloud.google.com/flows/enableapi?apiid=cloudbuild.googleapis.com&redirect=https://console.cloud.google.com/build/docs/private-pools/set-up-private-pool-environment["在此處啟用 Cloud Build API"^]。
* 確認 Console 代理程式的服務帳戶擁有所有標準權限。此外，請確保該服務帳戶擁有 `cloudbuild.workerpools.get` 和 `cloudbuild.workerpools.list` 權限。請參閱 https://docs.netapp.com/us-en/console-setup-admin/reference-permissions-gcp.html#service-account-permissions["控制台代理的 Google Cloud 權限"^]。


.步驟
. 使用此配置在與 Cloud Volumes ONTAP 部署相同的區域中建立私有工作池。有關建立私有工作池的資訊，請參閱 https://docs.cloud.google.com/build/docs/private-pools/create-manage-private-pools#creating_a_new_private_pool["Google Cloud 文件：建立和管理私有資源池"^]和 https://cloud.google.com/build/pricing["Google Cloud Build 定價"^]。
+
如果將 Cloud Volumes ONTAP 部署在受 VPC 服務控制保護的專案中，請在與 Console 代理程式相同的專案中建立私有工作資源池。工作資源池必須處於運作狀態。Google Cloud 中的預設公用 Cloud Build 工作資源池無法在服務邊界內運作。

+
工作池必須具有以下配置：

+
** 機器類型：e2-medium
** 磁碟大小：100 GB
** 指派外部 IP：False
** 網路：預設網路或專用網路。
** 已配置子網路以存取 https://cloud.google.com/apis["Google Cloud API"^]。請執行以下步驟以確保子網路可以存取 Google API：
+
... 請確保已為子網路啟用「Private Google Access」。
... 前往 *VPC Network 層級 > Private Service Access 標籤 > Allocated IP ranges for services*。
... 選擇 *Allocate IP range* 並為與 Google Compute Service 的私有連線分配內部 IP 範圍。
... 在 *Private connection to services* 中，選擇 *Create Connection*。
... 選擇 *Connected service producer = Google Cloud Platform*。
... 為上一個步驟中建立的私人連線 IP 範圍指派配置。




. 部署此工作池並保持其運行，以進行 Cloud Volumes ONTAP 管理。Google Cloud 使用此工作池在隔離環境中執行所有 Terraform 操作。
. 以私有模式部署 Cloud Volumes ONTAP 時，請在 *GCP Worker Pool* 欄位中選擇此工作池的名稱。請參閱 link:task-deploying-gcp.html["在 Google Cloud 啟動Cloud Volumes ONTAP"] 以取得相關說明。
+
如果您在受 VPC Service Controls 保護的專案中部署 Cloud Volumes ONTAP，請使用 API 建立 Cloud Volumes ONTAP 系統，並在建立要求主體中包含  `workerPool` 參數。

+

NOTE: 目前，使用控制台 UI 部署 Cloud Volumes ONTAP 時不支援包含工作資源池。對於受 VPC 服務控制保護的專案，API 是部署 Cloud Volumes ONTAP 的唯一支援方式。

[[network-configurations-to-support-console-agent-proxy]]
=== 支援控制台代理的網路配置

您可以使用為控制台代理程式設定的代理伺服器來啟用來自Cloud Volumes ONTAP存取。控制台支援兩種類型的代理：

* *明確代理*：來自Cloud Volumes ONTAP 的出站流量使用控制台代理代理程式設定期間指定的代理伺服器的 HTTP 位址。控制台代理管理員可能還配置了使用者憑證和根 CA 憑證以進行額外的驗證。Cloud Volumes ONTAP顯式代理程式有可用的根 CA 證書，請確保使用 https://docs.netapp.com/us-en/ontap-cli/security-certificate-install.html["ONTAP CLI：安全性憑證安裝"^]命令。
* *透明代理*：網路配置為透過控制台代理代理程式自動路由來自Cloud Volumes ONTAP 的出站流量。設定透明代理程式時，控制台代理程式管理員僅需要提供用於從Cloud Volumes ONTAP進行連接的根 CA 證書，而不是代理伺服器的 HTTP 位址。確保使用以下方式取得相同的根 CA 憑證並將其上傳到您的Cloud Volumes ONTAP系統 https://docs.netapp.com/us-en/ontap-cli/security-certificate-install.html["ONTAP CLI：安全性憑證安裝"^]命令。


如需為 Console 代理程式設定 Proxy 伺服器的相關資訊，請參閱 https://docs.netapp.com/us-en/console-setup-admin/task-configuring-proxy.html["配置控制台代理以使用代理伺服器"^]。

.在 Google Cloud 中為Cloud Volumes ONTAP設定網路標籤
在控制台代理程式的透明代理程式配置期間，管理員會為 Google Cloud 新增網路標籤。您需要取得並手動新增Cloud Volumes ONTAP配置的相同網路標籤。此標籤對於代理伺服器正常運作是必要的。

. 在 Google Cloud Console 中、找到您的 Cloud Volumes ONTAP 系統。
. 前往*詳細資料>網路>網路標籤*。
. 新增用於控制台代理的標籤並儲存配置。

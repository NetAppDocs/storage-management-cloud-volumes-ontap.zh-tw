= 了解 Cloud Volumes ONTAP 中的 BYOL 授權
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ./media/


[role="lead"]
自備授權（BYOL）是 Cloud Volumes ONTAP 的計費模式，在此模式下，您可以直接向 NetApp 購買授權，而不是使用雲端市場訂閱。

BYOL 適用於標準模式和私有模式部署，主旨於可用度限制。您可以在 NetApp Console 的 *授權和訂閱* 區段下的 *直接授權* 中管理 BYOL 授權。每個授權都與您的公司和特定的 NetApp 支援網站憑證相關聯。

* NetApp 已限制對具有有效市場訂閱的標準模式部署購買、延期和續約 BYOL 授權。如需詳細資訊，請參閱 https://docs.netapp.com/us-en/storage-management-cloud-volumes-ontap/whats-new.html#restricted-availability-of-byol-licensing-for-cloud-volumes-ontap["Cloud Volumes ONTAP的 BYOL 授權可用性受限"^]。
* NetApp 正在逐步淘汰基於節點的授權，轉而採用基於容量的授權。基於節點的授權仍適用於少數現有部署，包括部分 USPS 客戶部署以及在中國的部署。如需詳細資訊，請參閱 https://docs.netapp.com/us-en/storage-management-cloud-volumes-ontap/concept-licensing.html#end-of-availability-of-node-based-licenses["基於節點的許可證的可用性終止"^]。




[[byol-deployment-modes]]
== BYOL 部署模式

[role="tabbed-block"]
====
.標準模式部署
--
* 相較於 BYOL，NetApp 偏好採用年度或隨用隨付（PAYGO）市場訂閱來收取您的使用費。
* 標準模式部署通常使用基於容量的授權，而不是基於節點的授權。現有的標準模式部署中，只有少數使用基於節點的授權。


--
.私有模式部署
--
* 私有模式部署完全依賴 BYOL 授權，因為私有模式下無法使用市場訂閱。
* 對於新部署，請使用以容量為基礎的 Essentials 套件，而不是以節點為基礎的授權。一些較舊的私有模式部署使用以節點為基礎的授權。


--
====


[[compare-byol-license-types-in-private-mode]]
=== 在私有模式下比較 BYOL 授權類型

下表總結了私有模式下基於容量和基於節點的授權之間的差異。

[cols="25,37,38"]
|===
| 功能 | 基於容量的授權 | 基於節點的授權 


| 部署支援  a| 
新的私有模式部署僅支援基於容量的授權，特別是 Essentials 套件。
 a| 
新的私有模式部署不支援基於節點的授權。只有少數現有的基於節點的部署可以繼續使用它們。



| 購買  a| 
向 NetApp 購買基於容量的 BYOL Essentials 套件，並在部署期間將其分配給您的系統。
 a| 
如果您現有的私有模式部署採用節點型授權，您可以透過向 NetApp 購買 Essentials 套件，將其轉換為容量型授權。



| 容量  a| 
前 500 GiB 的已使用容量不計入您的授權費用。隨著工作負載需求的增加，您可以購買額外的套件。
 a| 
以節點為基礎的授權可為單一節點或 HA 配對提供高達 368 TiB 的容量。若要分配超過 368 TiB 的容量給 Cloud Volumes ONTAP 系統，請購買多個授權。例如，兩個授權可提供高達 736 TiB 的容量，四個授權可提供高達 1.4 PiB 的容量。



| 範圍  a| 
基於容量的授權會從 Cloud Volumes ONTAP 系統中共享的容量資源池提取資源。您可以根據儲存設備需求的變更重新分配可用容量。
 a| 
每個以節點為基礎的授權適用於一個 Cloud Volumes ONTAP 系統，並為該系統提供固定的容量。



| 可轉移性  a| 
每個以容量為基礎的授權都與一個 Console 帳戶相關聯。在該帳戶下建立的系統可以共享授權容量和序號。例如，一個 5 TiB 的授權可以支援兩個各 2.5 TiB 的系統，或是一個 5 TiB 的系統。您可以在 Console 中檢視授權序號，並將相同的授權指派給同一個帳戶下的多個系統。
 a| 
您可以透過刪除現有系統並使用該授權建立新系統來轉移基於節點的 BYOL 授權。只有 _雲端平台無關的_ 序號才能跨雲端供應商使用。這些序號以 _908xxxx_ 為前綴。

|===


[[manage-and-renew-byol-licenses]]
== 管理與續約 BYOL 授權



[[renew-a-byol-license]]
=== 續約 BYOL 授權

請聯絡 NetApp 代表續約您的 BYOL 授權。主控台會自動取得續約的授權，並將其安裝在 Cloud Volumes ONTAP 系統上。

如果控制台無法透過安全的網際網路連線存取授權檔案，請下載授權檔案並link:task-manage-node-licenses.html["手動將其上傳至主控台"]。

若要管理與主控台關聯的 NetApp 支援網站憑證，請參閱 https://docs.netapp.com/us-en/console-setup-admin/task-adding-nss-accounts.html["管理與 NetApp Console 關聯的 NSS 憑證"^]。



[[respond-to-an-expiration-warning]]
=== 對過期警告做出回應

主控台會在節點型授權到期前 30 天顯示警告，並在授權到期時再次顯示警告。選擇 Cloud Volumes ONTAP 系統以審查警告並續約授權。

image:screenshot_warning.gif["螢幕截圖：顯示包含警告圖示的Cloud Volumes ONTAP系統。該圖標表示需要採取行動。"]

如果您是組織管理員或帳戶管理員，並且已啟用該選項，則 Console 會在 Cloud Volumes ONTAP 報告中包含授權到期警告，並透過電子郵件將其傳送給您。

如果您未在授權到期前續約， Cloud Volumes ONTAP 系統將會關閉。在未續約授權的情況下重新啟動系統，會導致系統再次關閉。

Google Cloud 支援多種 Cloud Volumes ONTAP 組態。



[[supported-disk-types-in-google-cloud]]
== Google Cloud 支援的磁碟類型

除了使用者資料的儲存設備外，NetApp 還在 Google Cloud 上購買系統資料的雲端儲存。



[[internal-disks-for-system-data-in-single-node-systems]]
=== 單一節點系統中用於系統資料的內部磁碟

* 一個 10 GiB SSD 永久磁碟，用於儲存啟動數據
* 一個 64 GiB SSD 持久性磁碟，用於儲存根數據
* 一個 500 GiB SSD 持久性磁碟，用於NVRAM
* 一個 315 GiB 標準持久性磁碟，用於保存核心
* 啟動和根資料的快照
+

NOTE: 重新啟動時會自動建立快照。

* 預設情況下，啟動磁碟和根磁碟是加密的。




[[internal-disks-for-system-data-in-ha-pairs]]
=== HA 配對中用於系統資料的內部磁碟

* 兩個 10 GiB SSD 持久性磁碟用於啟動數據
* 四個 64 GiB SSD 持久性磁碟用於根數據
* 兩個 500 GiB SSD 持久性磁碟用於NVRAM
* 兩個 315 GiB 標準持久性磁碟，用於保存核心
* 一個 10 GiB 標準持久性磁碟，用於儲存中介數據
* 一個 10 GiB 標準永久磁碟，用於中介啟動數據
* 啟動和根資料的快照
+

NOTE: 重新啟動時會自動建立快照。

* 預設情況下，啟動磁碟和根磁碟是加密的。




[[google-cloud-storage-for-user-data]]
=== Google Cloud 使用者資料儲存設備

在 Google Cloud 中，聚合最多可以包含 6 個大小相同的磁碟。最大磁碟大小為 64 TiB。

磁碟類型可以是_區域 SSD 持久性磁碟_、_區域平衡持久性磁碟_或_區域標準持久磁碟_。您可以將永久性磁碟與 Google 儲存桶配對，以link:concept-data-tiering.html["低成本物件存儲"]。

Cloud Volumes ONTAP 在 9.18.1 及更新版本中支援單節點部署的 Hyperdisk Balanced 磁碟，並在 9.19.1 及更新版本中支援單一可用區域 （AZ） 中的高可用性 （HA） 組態。



[[supported-disk-sizes]]
=== 支援的磁碟大小

在 Google Cloud 中，一個 Aggregate 最多可以包含 6 個相同類型和大小的磁碟。支援下列磁碟大小：

* 100 GB
* 500 GB
* 1 TB
* 2 TB
* 4 TB
* 8 TB
* 16 TB
* 64 TB




[[supported-configurations-by-license]]
== 授權支援的組態

Cloud Volumes ONTAP 在 Google Cloud 中既可以作為單節點系統使用，也可以作為高可用性（HA）節點對使用，以實現容錯和不間斷操作。

不支援將單節點系統升級為 HA 配對。如果您想在單節點系統和 HA 配對之間切換，則需要部署新系統並將資料從現有系統複寫到新系統。

Cloud Volumes ONTAP 可以在雲端供應商的保留或隨選 VM 執行個體上執行。不支援使用其他 VM 執行個體類型的解決方案。

控制台顯示 Standard 和 BYOL 新增了一種支援的機器類型：n1-highmem-4。但是，這種機器類型不適用於生產環境。我們僅將其用於特定的實驗室環境。.^5^ 您可以在 https://docs.netapp.com/us-en/storage-management-cloud-volumes-ontap/whats-new.html#support-for-next-generation-google-cloud-vms-in-cloud-volumes-ontap-ha["Cloud Volumes ONTAP 9.19.1 及更高版本，適用於單一 AZ HA 部署"^]上部署下一代 C3 系列虛擬機器。c3-standard-44 和 c3-standard-88 機器及其 LSSD 變體預設支援 Google Cloud Console 中的 Tier-1 頻寬。如需有關 LSSD 變體的詳細資訊，請參閱link:reference-configs-gcp.html#flash-cache-support["Flash Cache 支援"]。

[[flash-cache-support]]
== Flash Cache 支援

從 Cloud Volumes ONTAP 9.13.0 開始、以下 HA 配對部署執行個體可使用 _Flash Cache_ 、高寫入速度、以及 8,896 位元組的較高最大傳輸單元（MTU）：

* n2-標準-16
* n2-標準-32
* n2-標準-48
* n2-標準-64


部署符合條件的執行個體類型時、您可以啟用 _Flash Cache_ 和高寫入速度。若要啟用 8,896 位元組的較高最大傳輸單元、您必須為部署選擇 VPC-1 、 VPC-2 或 VPC-3 。較高的 MTU 可實現較高的網路處理量。如需啟動其中一項部署的詳細資訊、請參閱 https://docs.netapp.com/us-en/bluexp-cloud-volumes-ontap/task-deploying-gcp.html["在 Google Cloud 啟動 Cloud Volumes ONTAP"^]。


NOTE: _Flash Cache_、高寫入模式和 MTU 為 8,896 是功能相關的，無法在已設定的執行個體中個別停用。

Cloud Volumes ONTAP 9.18.1 及更高版本支援單節點部署的 C3 系列虛擬機器本機 SSD （LSSD） 變體，Cloud Volumes ONTAP 9.19.1 及更高版本支援單一可用區 （AZ） 中 HA 部署的 C3 系列虛擬機器本機 SSD （LSSD） 變體。對於這些部署，如果您選擇 C3 系列虛擬機器的本機 SSD （LSSD） 變體，則預設會啟用 Flash Cache。即使目標變體支援 Flash Cache，您也無法在 Cloud Volumes ONTAP 部署中切換 C3 LSSD 虛擬機器變體。

請查看下表，以了解虛擬機器變體及其支援的 LSSD 數量：

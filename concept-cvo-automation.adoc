= 了解 Cloud Volumes ONTAP 自動化選項
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ./media/


[role="lead"]
DevOps 團隊使用各種工具來自動化資料中心執行環境的設定和管理。除了 NetApp Console 之外，您還可以使用多種技術來實現 Cloud Volumes ONTAP 的自動化，包括 NetApp Console API、ONTAP CLI 流程以及 Ansible 和 Terraform 等自動化工具。這些外部自動化工具通常基於基礎架構即程式碼（IaC）設計。

使用 https://labondemand.netapp.com/["隨需實驗室"^]來練習自動化 Cloud Volumes ONTAP。



[[netapp-console-apis]]
== NetApp Console API

NetApp Console 提供 REST API，可用於以程式設計方式管理 Cloud Volumes ONTAP 資源。這些 API 支援建立和管理 Cloud Volumes ONTAP 系統，以及在 Amazon Web Services（AWS）、Microsoft Azure（Azure）和 Google Cloud 上新增彙總和 Volume 等作業。可用的 API 呼叫因雲端供應商和部署類型（包括單節點和高可用度（HA）組態）而異。

您可以使用 Cloud Volumes ONTAP API 工作流程來自動化典型的部署和後續儲存設備管理。一些工作流程包括準備部署、建立系統和管理儲存設備，並提供針對 AWS 、 Azure 和 Google Cloud 的特定供應商工作流程。

[cols="2,2,3"]
|===
| 活動 | 使用的 API 和介面 | API 參考 


| 建立 Cloud Volumes ONTAP 系統。API 呼叫因雲端供應商和單節點或 HA 部署而異。 | NetApp Console REST API 和 Cloud Volumes ONTAP API 工作流程  a| 
* https://docs.netapp.com/us-en/console-automation/cm/wf_aws_cloud_create_we_capacity.html["AWS：建立系統"^] - `POST /occm/api/vsa/working-environments` 或 `POST /occm/api/aws/ha/working-environments`
* https://docs.netapp.com/us-en/console-automation/cm/wf_azure_cloud_create_we_capacity.html["Azure：建立系統"^] - `POST /occm/api/azure/vsa/working-environments` 或 `POST /occm/api/azure/ha/working-environments`
* https://docs.netapp.com/us-en/console-automation/cm/wf_gcp_cloud_create_we_capacity.html["Google Cloud：建立系統"^] - `POST /occm/api/gcp/vsa/working-environments` 或 `POST /occm/api/gcp/ha/working-environments`




| 為 Cloud Volumes ONTAP 系統建立彙總。 | NetApp Console REST API  a| 
* https://docs.netapp.com/us-en/console-automation/cm/wf_aws_ontap_create_aggr.html["AWS：建立彙總"^] - `POST /occm/api/vsa/aggregates` 或者 `POST /occm/api/aws/ha/aggregates`
* https://docs.netapp.com/us-en/console-automation/cm/wf_aws_cloud_add_capacity.html["AWS：新增容量至 Elastic Volume 彙總"^] - `POST /occm/api/vsa/aggregates/{workingEnvironmentId}/{aggregateName}/add-capacity` 或 `POST /occm/api/aws/ha/aggregates/{workingEnvironmentId}/{aggregateName}/add-capacity`
* https://docs.netapp.com/us-en/console-automation/cm/wf_aws_ontap_add_disks_aggr.html["AWS：新增磁碟至彙總"^] - `POST /occm/api/vsa/aggregates/{workingEnvironmentId}/{aggregateName}/disks` 或  `POST /occm/api/aws/ha/aggregates/{workingEnvironmentId}/{aggregateName}/disks`




| 為 Cloud Volumes ONTAP 系統設定 CIFS 伺服器。 | NetApp Console REST API  a| 
* https://docs.netapp.com/us-en/console-automation/cm/wf_aws_ontap_create_cifs.html["AWS：建立 CIFS 伺服器組態"^] - `POST /occm/api/vsa/working-environments/{workingEnvironmentId}/cifs` 或 `POST /occm/api/aws/ha/working-environments/{workingEnvironmentId}/cifs`
* https://docs.netapp.com/us-en/console-automation/cm/wf_azure_ontap_create_cifs.html["Azure：建立 CIFS 伺服器組態"^] - `POST /occm/api/azure/vsa/working-environments/{workingEnvironmentId}/cifs` 或 `POST /occm/api/azure/ha/working-environments/{workingEnvironmentId}/cifs`
* https://docs.netapp.com/us-en/console-automation/cm/wf_gcp_ontap_create_cifs.html["Google Cloud：建立 CIFS 伺服器組態"^] - `POST /occm/api/gcp/vsa/working-environments/{workingEnvironmentId}/cifs` 或 `POST /occm/api/gcp/ha/working-environments/{workingEnvironmentId}/cifs`




| 在 Azure 和 Google Cloud 中建立和管理額外的資料服務儲存設備 VM，並設定其所需的網路介面。 | 適用於 NetApp Console 的 Cloud Volumes ONTAP API  a|

| 建立使用客戶管理加密金鑰的 Cloud Volumes ONTAP 系統。 | NetApp Console API  a|

| 部署後修改 Azure Premium SSD v2 磁碟的 IOPS 和處理量設定。 | Cloud Volumes ONTAP API  a|

[[ontap-cli]]
== ONTAP CLI

您可以使用 ONTAP CLI 執行多項 Cloud Volumes ONTAP 管理任務。可用步驟和命令因功能和雲端供應商而異。請勿使用 ONTAP CLI 或 ONTAP System Manager 升級 Cloud Volumes ONTAP。請從 NetApp Console 執行升級。

[cols="2,2,3"]
|===
| 活動 | CLI 程序或命令 | 參考資料 


| 為 Cloud Volumes ONTAP 設定加密金鑰管理。 | ONTAP CLI 中的 AWS KMS、Azure Key Vault 或 Google Cloud KMS 指令  a| 
link:task-aws-key-management.html["設定 AWS KMS 金鑰管理"] link:task-azure-key-vault.html["設定 Azure Key Vault 金鑰管理"] link:task-google-key-manager.html["設定 Google Cloud KMS 金鑰管理"]



| 設定事件管理系統（EMS）事件目的地和路由。 | ONTAP CLI 中的 EMS 組態指令 | link:task-configure-ems.html["配置 EMS"] 


| 為現有的 Cloud Volumes ONTAP 叢集設定 NTP 伺服器。 | `cluster time-service ntp server create` | link:task-sync-time.html["設定 NTP 伺服器"] 


| 建立儲存效率已停用的 Volume 時，請停用資料壓縮。 | ONTAP CLI Volume 效率指令  a| 
link:concept-flash-cache.html["審查儲存效率選項"] link:reference-limitations-aws.html["查看 AWS 儲存效率限制"]



| 建立額外的 LUN。 | ONTAP CLI 中的 LUN 建立指令 | link:task-create-volumes.html["建立 Volume 和額外的 LUN"] 


| 建立停用 WORM 的 Volume，或為 SnapLock Volume 建立 Snapshot 快照技術複本（視情況而定）。 | ONTAP CLI 中的 Volume 和 Snapshot 快照技術管理指令  a| 
link:concept-worm.html["管理 WORM 儲存設備"] link:reference-worm-snaplock.html["為 WORM 儲存設備建立 Snapshot 快照技術副本"]



| 設定 NVFAIL 行為，以協助防止在資料遺失事件發生後存取資料，直到問題解決。 | ONTAP CLI 中的 NVFAIL 組態指令 | link:concept-write-speed.html["設定 NVFAIL"] 


| 在 Azure 單節點部署中隔離 SnapMirror 複寫流量。 | ONTAP CLI 連網和 SnapMirror 指令 | link:task-segregate-snapmirror-azure.html["在 Azure 中隔離SnapMirror流量"] 
|===
如需更多資訊，請參閱  https://docs.netapp.com/us-en/ontap-cli/man.html["ONTAP CLI 參考指南"^]

== Terraform
